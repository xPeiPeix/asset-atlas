# 维护资产地图

把已经拥有的项目变成以后找得到、用得上、维护得了的资产。一个资产只有一张详细卡片；README 提供导航，可视化页面从卡片生成，避免维护多套不一致的说明。

## 制作第一张卡

用户要求首次建库或制作第一张卡时，先完整读取 [首次制卡指令](references/first-card.md)，按其中流程选择固定资产库目录、整理项目并打开本地卡片。安装 skill 只提供操作说明，制卡仍由用户的本地编程助手执行。

首次制卡只修改私人资产库，不修改被登记项目，跳过下文的项目反向登记。常规查询与后续维护仍按下面的流程执行。

## 找到现有索引

1. 优先使用用户本次指定的索引根目录；其次读取当前项目适用的 `AGENTS.md`，查找 Asset Atlas 登记块或明确的索引位置。
2. 没有指定位置时，检查当前目录是否包含 `README.md`、`tools/`、`archive/`、`templates/tool-entry.md`。发现唯一符合结构的现有索引后使用它；发现多个候选时，请用户选定。
3. 没有找到索引时，说明尚未找到；首次建账先请用户选定目录，不在技能目录或其他位置擅自另建一套。用户已明确指定创建目录时直接使用该目录。
4. 选定后读取适用的 `AGENTS.md` 和索引 README；写入前记录 `git status --short`（若为 Git 仓库）。目录或模板缺失时先说明，不能当作空白索引继续登记。

本技能没有固定机器路径，也没有默认远端主机。路径示例不代表用户的实际资产。

## 文件职责

| 文件 | 用途 |
| --- | --- |
| `README.md` | 项目介绍、安装使用与导航，不维护逐项资产清单 |
| `tools/T-NNN-slug.md` | 活动资产的唯一详细事实源 |
| `archive/T-NNN-slug.md` | 归档资产的唯一详细事实源 |
| `tools/T-000-asset-atlas.md` | 资产地图自身的保留卡片 |
| `templates/tool-entry.md` | 新卡片模板；按需删去不适用的可选字段 |
| `asset-atlas.html` | 自动生成的可视化页面，不直接维护其中的资产事实 |

头像是可选视觉资源，不影响资产登记。复杂资产可以在卡片内按项目现有格式补充组件关系或业务流程；简单工具不必画图。

需要专属头像时读取 [原生代码绘制头像](references/code-avatars.md)。以当前可调用的工具为准：有 ImageGen 可以生图；没有生图工具的助手（包括未接入此类工具的 Claude）直接编写 SVG、Canvas 等绘图代码，导出合规 WebP。不要把特定模型或生图服务作为安装或制卡条件。

## 查询与取证

- 查询总体清单时读取 `tools/` 和 `archive/` 中的卡片；查单个资产时，用 `rg` 按名称、ID、路径、仓库地址或入口搜索这两个目录，再读命中卡片全文。
- **查询只读**：不修改卡片、补登记、构建页面、提交或部署。需要细节时按卡片回答，不把模板和其他资产的信息混入结果。
- 明确区分“卡片记录”“本次已验证”和“未核验”。只把实际检查的绝对日期 `YYYY-MM-DD` 写入“最近核验”；仅改文案不刷新日期。部分核验时说明检查了哪些内容。
- 使用本地目录、项目 README、Git remote 或用户提供的信息取证。只验证当前请求涉及的内容；维护索引不代表获准连接远端主机、访问账号后台或修改其他系统。
- 不把目录、容器或域名的存在等同于资产归属已经确认。存疑时标注待确认，不自行认领。

## 一资产一卡与永久 ID

- 资产可以是本地小工具、网站、服务，也可以是没有网页入口的定时任务。按实际用途和独立维护方式登记，不以代码量或是否公网可访问作为门槛。
- 新增前按名称、目录、仓库和入口查重。同一项目的前端、数据库、定时任务通常写在同一张卡；只有确实独立使用、停用或维护时才另建资产。
- `T-000` 永久保留给 Asset Atlas 自身，标题为 `# T-000 · Asset Atlas`。普通资产从 `T-001` 起编号。
- 永久 ID 在活动和归档卡片中全局唯一。分配当前最大编号加一，不补空号，归档后不复用；`npm run check` 输出 `next_id` 时使用其结果。
- 文件名采用 `T-NNN-lower-kebab-slug.md`，标题采用 `# T-NNN · 资产名称`，两处 ID 一致。改名不改变永久 ID。
- 资产清单从卡片生成，不把每张卡的摘要再复制到 README。

## 写入与核验

1. 读取目标卡片或模板及查重结果，保留当前仓库中已有改动。
2. 按用户请求完成一种操作：新增唯一卡片；原位更新；在指定范围核验；或在用户确认停用后将卡片移到 `archive/`。归档保留 ID，补充日期和原因，不直接删除历史卡片。
3. 只写已知事实。在标题后用 `> 一句话用途` 写摘要。`状态`、`分类`、`主维护位置`、`最近核验` 为必填字段；日期未知时用“未核验”。入口、目录、启动方法、依赖、数据和备份等按用途填写，不猜地址或成功状态。
4. 摘要变化时更新原卡。卡片移动或改名时同步引用它的链接。不要另建手写资产数组，也不要直接编辑生成页面。
5. 有已确认且可写的本地项目时，按下节维护反向登记；没有本地项目则跳过，不编造路径。
6. 在索引根目录运行 `npm run check`，修复本次修改引入的问题。回读卡片、README 和相关 diff，确认生成页面来自当前卡片。检查失败时明确报告原因，不把构建成功说成资产运行正常。
7. 说明修改了哪些 ID、哪些事实得到验证、哪些仍未核验，以及反向登记和检查结果。提交、推送、发布或部署按用户另行给出的授权执行；`npm run check` 不包含这些授权。

运行项目需要 Node.js 22 或更新版本；依赖尚未安装时先执行 `npm install`。用户只要求重新生成页面时可用 `npm run build`，需要本地预览时用 `npm run serve`。不因维护一张卡片而修改被登记项目的实现、运行配置或账号。头像、关系图、额外统计等只在有需要时补充。

## 项目反向登记

让项目自己知道它对应哪张资产卡，以后修改入口或启动方法时更容易同步资料。

- 仅在用户授权新增、更新或核验资产时，对卡片中已确认存在且可写的本地项目建立登记。用 `git rev-parse --show-toplevel` 或项目结构确认根目录，完整读取该目录的 `AGENTS.md` 并检查 Git 状态后再编辑。
- 保留现有指令，只维护下面的登记块；没有 `AGENTS.md` 时可创建仅含登记块的最小文件。同一项目有多个资产时保留各自条目。单体仓库的独立子项目使用适当的子目录，避免影响无关项目。
- 使用实际卡片绝对路径，便于从项目找到索引。下例中的路径只作格式说明，不得原样写入实际登记。

```markdown
<!-- asset-atlas-registration:start -->
## Asset Atlas 登记

- 永久 ID：`T-001`
- 资产卡片：`~/Projects/example/tools/T-001-example.md`（写入时替换为实际绝对路径）
- 用途、入口、位置、启动方式、运行状态或数据与 Secrets 存放位置发生变化时，使用 `$manage-asset-atlas` 同步这张卡片；普通实现细节变化不需要更新。
<!-- asset-atlas-registration:end -->
```

- 卡片仍是详细事实源，不把整张卡片复制到 `AGENTS.md`。归档或移动卡片时更新反向链接；回读 ID 和路径，并运行 `git diff --check`。
- 登记改动保留在项目工作区并在完成汇报中说明，不自动提交其他项目。项目不可写、路径缺失或已有登记冲突时说明情况，不把索引更新扩大为权限修复或迁移任务。

## 内容要求

- Secrets 只记录存放位置或管理方式，绝不记录密码、Token、Cookie、私钥或连接串的值。示例使用 `example.invalid`、`host-example` 或 `~/Projects/example` 等明显的占位内容。
- 卡片可能包含私人目录、入口和服务信息；生成页面也包含这些事实。发布开源程序不等于公开用户的真实卡片或生成页面。用户要求公开时，核对将要公开的具体内容，示例与私有数据分开。
- 保留可复制的路径、命令和可点击链接；不要用含凭证的 URL 充当入口。字段尽量回答“做什么、在哪、怎么用、现在是否可用”，无需为了填满模板补无用内容。
